Pingo Engine

A tiny 2D engine for pixel games, written in C++ with raylib. You build your scenes while the game runs, place characters with the mouse, and when you're happy, one key press brings the world to life.

The heart of it

Everything is a scene

Your game is a bunch of scenes: a main menu, a little town, a battle. In the Development build they all sit at the top of the window like browser tabs. Click one and you're in. Every scene is also its own editor, so there is no separate tool and no export step.

Menu

Texts and buttons

Title screens and menus. Buttons jump to another scene, open the settings or quit. There is always at least one menu, and one of them is the entry point where the game starts.

Tileset

A world made of tiles

A map built from 32 pixel tiles, like a town or an overworld. The player walks from tile to tile and the camera follows. Every tile shows its number while you build.

Normal

Free placement

Characters stand wherever you drop them, pixel perfect. Heroes and enemies, health bars, a background image and its own music. Great for battles.

Psst! You can click the tabs below, just like in the engine.

Switching is one click

Jump from a tile world into a battle and back without restarting anything. The tab tells you where you are, the lock icon tells you whether the scene is protected. Go on, try it:

Make a new scene

Hit the + right next to the last tab. Two tiny windows later you're standing in your new scene.

1

Name and type

Give it a name and pick Menu Tileset or Normal from the dropdown.

2

Pick a template

None starts empty and black. Default copies the scene you already know: Main Menu, Hub or Combat.

3

Tweak the options

Each type brings its own: a tileset asks for columns and rows, a menu can become the entry point.

4

You're in!

Create switches right into it. The new tab is unlocked, so you can start editing at once.

Tab tricks

Right click any tab for its menu: Edit, Duplicate, Lock and Delete. Everything you change lands straight in assets/scenes/scenes.json.

So many scenes!

When the tab bar fills up, long names get politely shortened with a little while short ones keep their full width. Duplicate copies a scene with all of its files, handy for trying out a variation without breaking the original.

Normal scenes

Build with objects

In a Normal scene you arrange your characters right on the battlefield. Everything saves the moment you let go, and object types are shared by all scenes, so a new enemy can show up anywhere.

Pick it up, move it

  • Click a character: four arrows, its coordinates and its name appear.
  • Drag it with the mouse, the cursor turns into a grabbing hand.
  • ← → ↑ ↓ nudge by one pixel, with Shift by ten.
  • Characters are drawn by their feet, so whoever stands lower appears in front.

Add anything

Right click into empty space and the Add menu lists every character type from assets/characters. Pick one and it appears exactly where you clicked.

Right click a type in that menu to duplicate or delete it.

Invent a new object

The last item, +New, opens a little form: name, size, health and color. You get a colorful placeholder you can place and test right away, long before its sprite is drawn. Health 0 makes it indestructible, like a crate or a wall.

Duplicate, swap, delete

Right click a character for Duplicate, Swap Team (heroes and enemies trade places) and Delete. Del or Backspace deletes the selection too, and deleting always asks first.

Oops? Undo!

As soon as something changed, Changes detected lights up in the corner. Z steps back, Y steps forward again, as often as you like while the scene is open.

Built something? Now watch it move!

Press play

While you build, the world holds its breath. Shift + Enter plays the open scene exactly like the Debugging build, Shift + Esc puts you back into the editor, right in the scene you're in.

The tabs step aside and the scene name moves to the top left. The little Development label stays, so you never mix it up with the real game.

Tileset scenes

Paint tiles

Every tile wears its number. Click a tile and type a digit, or right click it and pick from the list. There is no save button: each change is written instantly.

Maps are just text

A map is a plain text file, one digit per tile. What the digits mean, which tiles you can walk on and where they sit in the sprite atlas lives in assets/tilesets/overworld.json. Lines starting with # are comments.

Menu scenes

Menus without code

Menus work with the same editor as characters: click to select, drag to move, right click to add. Shift + click runs a button, so you can test where it leads.

Little extras

The small things that make it feel like a real engine.

A proper splash screen

Release and Debugging builds greet you with Pingo, “Made with Pingo Engine” and the version. It fades in and out, any key or click skips it.

Three build modes

  • Release: the finished game, no tools.
  • Debugging: playable, plus FPS, hitboxes and scene keys.
  • Development: the world stands still. Scene tabs, editors and a free camera you steer with WASD or the arrows. It starts right at the entry point.

A cursor that cares

The mouse is a little pixel hand that glows yellow over anything clickable and grabs while you drag.

Characters from JSON

A character is a small file in assets/characters: sprite atlas, frames, animation speed, move speed, hitbox and shadow. Collisions, health bars and the selection ring come for free.

Music per scene

A Normal scene names its track in its file. Entering another scene switches the music, and if both use the same track it simply keeps playing.

Let's go

Get it running

You need a C++20 compiler, CMake 3.20 or newer, raylib and nlohmann/json. On macOS, Homebrew brings all of them in one line.

With the terminal

  1. Install the tools and libraries: 
    brew install cmake raylib nlohmann-json
  2. Get the code: 
    git clone https://github.com/V-Q-M/Pingo-Engine.git
cd Pingo-Engine
  3. Configure, build and start, here in the Development mode: 
    cmake -S . -B build -DPINGO_BUILD_MODE=Development
cmake --build build
cd build && ./PingoLegends

Start the game from inside build: it loads assets/ relative to the working directory, and every build copies the assets there. Swap Development for Debugging or Release to build the other modes, ideally each in its own build folder.

With CLion

  1. Install the libraries as shown on the left (CLion brings its own CMake).
  2. Open the Pingo-Engine folder. CLion picks up the three CMake profiles that come with the project: Release, Debugging and Development.
  3. Choose a profile in the toolbar, pick the PingoLegends run configuration and press Run.

Each profile builds into its own folder, like cmake-build-development, and sets PINGO_BUILD_MODE for you. Assets are copied on every run, so a tweaked JSON file always reaches the game.

Good to know

  • In Development, the editors save into the build folder and back into the project's assets/, so your changes survive the next build.
  • The engine is made and tested on macOS. On Linux or Windows, install raylib and nlohmann/json so CMake's find_package can find them.

Where things live

The engine lives in src/Engine and knows nothing about Pingo. The game in src/Game defines the three scene types and registers them. Everything you build in the editors ends up as plain files in assets/, easy to read and easy to commit.

Have fun building!
